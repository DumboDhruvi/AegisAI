# AegisAI — Enterprise Data Governance & Security Policy

This document formally specifies data ingestion, access control, audit logging, and data retention policies for the AegisAI platform as mandated by Module 13.

---

## 1. What Data Enters the System
1. **Source Documents:** Ingested enterprise documents (internal wikis, technical manuals, policy documents).
   - Validated for UTF-8 encoding, schema integrity, and duplicate content before indexing.
   - Scanned for indirect prompt injection and corpus poisoning before chunking.
2. **User & Evaluation Prompts:** Test queries, golden test cases, and real-time user inputs.
   - Scanned for secrets (API keys, credentials) and PII (SSNs, phone numbers, credit card numbers).
   - Sanitized via automated masking before storage or downstream model evaluation.
3. **Model Responses & Evaluation Traces:** Outputs generated by candidate LLMs and intermediate tool execution traces.

---

## 2. Who Can Access the System (RBAC & Clearance Levels)
Access to resources in AegisAI is governed by a strict hierarchical clearance policy:

| Access Level    | Permitted Clearance | Permitted Operations |
| --------------- | ------------------- | -------------------- |
| `PUBLIC`        | All authenticated users | Query public documentation, run evaluation on public datasets |
| `INTERNAL`      | Employees and verified services | Retrieve internal architecture docs, run internal benchmarks |
| `CONFIDENTIAL`  | Departmental teams, QA engineers | Evaluate private roadmap docs, model cost and pricing logs |
| `RESTRICTED`    | Security Admins, Compliance Officers | Access unredacted audit trails, modify retention policies |

Rule: Actors can only access resources whose clearance classification is equal to or lower than their own clearance level. Any access denial is immediately logged.

---

## 3. What Is Logged (Audit Logs & Telemetry)
All critical operations generate an immutable `AuditLogEntry` capturing:
- **Timestamp:** Exact UTC event time.
- **Actor Identity:** User ID, service account, or API key identifier.
- **Action:** `INGEST`, `EVALUATE`, `QUERY`, `EXPORT`, `PURGE`, or `ACCESS_DENIED`.
- **Resource ID:** Unique identifier of target document, dataset, or model.
- **Access Level:** Clearance level of the accessed resource.
- **Status:** `SUCCESS` or `DENIED`.
- **Details:** Contextual parameters including requested clearance and IP address.

---

## 4. What Is Retained (Data Retention Policy)
Compliance rules dictate the retention windows for stored assets:

| Asset Category       | Retention Window | Purge Trigger |
| -------------------- | ---------------- | ------------- |
| Raw Input Prompts    | 30 days          | Automated retention job (`enforce_data_retention`) |
| Evaluation Traces    | 90 days          | Automated retention job (`enforce_data_retention`) |
| Audit Trail Logs     | 365 days (1 yr)  | Automated retention job (`enforce_data_retention`) |
| Golden Test Datasets | Indefinite       | Versioned baseline snapshots retained permanently |
